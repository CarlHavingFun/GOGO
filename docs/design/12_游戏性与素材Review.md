# 12｜游戏性与素材 Review

- **版本**：v0.2
- **日期**：2026-07-29
- **评审范围**：产品定位、核心循环、枪械、角色、敌人、奖励、20 波、素材拆分、AI 生图、Godot 落地

## 2. 已确认的优势

### 2.1 不是简单换皮 Brotato

项目的核心不是“六把枪自动攻击”，而是：

- 手动瞄准；
- 后坐力与准星恢复；
- 弹匣与换弹窗口；
- 弱点与射击节奏；
- 投掷物改变空间；
- 角色缺点进入敌人行为与构筑。

这些机制能形成独立于参考作品的操作身份。

### 2.2 五把枪有明确操作语言

- USP：连续命中与稳定成长；
- Deagle：射击节奏与过量伤害；
- AK：后坐力管理与失控转收益；
- M4：稳定压制与连续命中；
- AWP：激光预瞄、贯穿与长换弹窗口。

这套区分比“伤害、射速、弹匣不同”更有价值。后续不能为了平衡把五把枪拉回同一种手感。

### 2.3 角色负面天赋是核心卖点

尼尼的背身干扰、设备的诱饵、大表哥的烟雾依赖都能产生故事性和重开动力。正确方向不是删除缺点，而是确保缺点满足：

1. 可预警；
2. 可规避；
3. 可缓解；
4. 可反转；
5. 不夺取玩家控制；
6. 不通过隐藏概率让射击无效。

### 2.4 敌人以职责提出问题

追击、包围、远程预警、护盾、维修、诱饵、烟幕猎犬等职责可以组成有意义的波次，而不需要为每波制作一种新怪。

## 3. P0 问题：必须在开发前修正

### P0-1｜文档出现双重真相

仓库同时存在：

- 完整的 `docs/design/00～11`；
- 后续新增的 `docs/00～07` 简化文档；
- 两份以 `.md.rtf` 保存的素材文档。

问题：

- Codex 无法判断哪个是权威规则；
- 相同编号指向不同内容；
- 简化版遗漏了关键约束；
- RTF 文件不适合代码审查、全文搜索和自动处理。

处理决定：

- `docs/design/` 为唯一设计真相；
- 删除重复的 `docs/00～07`；
- 将 RTF 素材文档替换为真正 Markdown；
- 使用 `CODEX_START.md` 作为唯一开发入口。

### P0-2｜首个实现范围过大

直接要求 Codex 实现五角色、五枪、47 升级、20 波，会造成：

- 射击手感尚未验证就被大量系统包围；
- bug 来源难以定位；
- 素材需求一次性膨胀；
- Agent 容易做出“能运行但不好玩”的大壳子。

处理决定：

- M0 只做 AK 射击玩具；
- M1 只做五波闭环；
- M2 只用尼尼与大表哥验证角色缺点和烟雾；
- M3 后再进入十波垂直切片。

### P0-3｜素材规范缺少工程字段

现有“角色、枪械、特效分开”是正确原则，但不足以直接生产。每个资产还必须定义：

- `asset_id`；
- 最终路径；
- 逻辑尺寸；
- 画布尺寸；
- 锚点；
- 朝向；
- 动画帧；
- 动画 FPS；
- 碰撞参考；
- 色板限制；
- Prompt；
- 负面约束；
- Godot 导入设置；
- 状态与验收人。

处理决定：新增 `13_素材生产管线与提示词.md` 和 `assets/asset_manifest.csv`。

## 4. P1 游戏性问题与修改建议

### P1-1｜“背身失误”不能直接降低命中率

不推荐：

- 隐藏概率让子弹偏离；
- 命中后随机判定失效；
- 系统直接降低玩家鼠标精度。

推荐实现：

- 背身诱导怪在进入射程前做明显转身动作；
- 尼尼瞄准其背部时，准星恢复速度降低或弱点暂时隐藏；
- 玩家绕侧、等待怪物转身、使用闪光或击杀诱导源都能处理；
- 后期模块可把“背身目标”转成蓄力、暴击或赏金收益。

这样保留梗，同时失败仍可解释。

### P1-2｜设备的“好皮肤诱惑”需要战斗化

不推荐：弹窗强制玩家选错武器或打断战斗。

推荐：

- 敌人掉落高亮假收藏品；
- 接近后出现 0.6 秒识别窗口；
- 真收藏品提供临时增益，假收藏品生成诱饵、爆炸或暴露位置；
- 设备能更早看见稀有度，但假货对其吸引半径更大；
- 构筑可选择“鉴定流”或“贪婪流”。

### P1-3｜大表哥不能变成烟雾里站桩

必须存在：

- 烟雾边缘收益；
- 烟雾结束收益；
- 移动或重新布烟收益；
- 能进入烟雾逼位的敌人；
- 不能完全否定烟雾的敌人。

建议把最强收益放在“进入、离开、边缘和结束”事件，而非长期待在中心。

### P1-4｜20 波需要波次预算，不是固定数量表

每波定义：

- 总威胁预算；
- 同屏软上限；
- 各职责占比；
- 生成间隔曲线；
- 精英预算；
- 事件插槽；
- 远程和控制单位上限；
- 失败遥测字段。

固定编队只用于黄金种子和回归测试，普通运行由预算与受控随机生成。

### P1-5｜升级池要治理垃圾候选

候选生成顺序建议：

1. 删除前置不满足和已失效候选；
2. 删除明确冲突；
3. 应用角色、武器、已有标签相关权重；
4. 应用连续未出现保底；
5. 控制同类候选数量；
6. 至少保留一个修补型或通用型选择；
7. 记录候选为何出现与为何被过滤。

关键指标：

- 单升级选择率高于 75%：疑似必选；
- 低于 5%：疑似垃圾、条件不清或数值不足；
- 第 8～10 波仍无法描述流派：构筑发动机出现太晚；
- 重开后重复选择完全相同：定向权重过强。

## 5. P1 素材设计问题与修改建议

### P1-1｜风格不能只写“Brotato 风”

必须拆成可验收语言：

- 俯视 3/4 视角；
- 大头小身体块；
- 强轮廓；
- 低频细节；
- 每个角色 2～3 个识别锚点；
- 每个敌人一个主轮廓特征；
- 每个危险机制一个预警形状；
- 限制局部色数；
- 透明背景；
- 无文字、无 UI、无场景；
- 不复制参考游戏角色比例、具体轮廓、色板或资产。

“受同类作品启发”不等于复制其具体美术表达。

### P1-2｜角色动画不应单独画“shoot”全身帧

因为武器独立旋转，角色主体建议优先生产：

- `idle`：4 帧轻微呼吸；
- `walk`：6 或 8 帧；
- `hit`：2 帧；
- `death`：6 帧；
- `skill`：按角色需要；
- `portrait`：独立 UI 资产。

射击反馈主要由：

- 武器后坐位移；
- 枪口火焰；
- 手臂或身体轻微反冲；
- 镜头与音效；
- 曳光与命中反馈

共同完成。不要为五把枪分别制作五套角色射击动画。

### P1-3｜武器需要统一握持与朝向基准

所有武器：

- 默认枪口朝右；
- 握持点统一记录；
- 枪口点独立记录；
- 弹壳点可选；
- 图片中不包含手、人物、火焰、子弹和阴影；
- 旋转由 Godot 节点完成；
- 左向使用节点翻转或统一旋转规则，不另画一套。

### P1-4｜特效必须兼顾性能和可读性

- 烟雾不能用高频透明噪点铺满屏幕；
- 燃烧地面需要清晰安全边界；
- 闪光不对白屏，转为敌人控制和短促高亮；
- 爆炸中心、伤害范围和余波分层；
- 敌方危险预警颜色优先级高于玩家装饰特效；
- 同屏高峰时允许减少粒子和次级碎片，但不能减少危险提示。

在 M0 灰盒手感通过后，第一批只生产：

| 场景 | 1 | 竞技场地面与边界套件 |

不要在 M0 前生成五角色全动画和所有 20 波素材。

## 7. 必须记录的遥测

### 战斗

- 每把枪命中率；
- 弱点命中率；
- 平均连续射击时长；
- 空仓次数；
- 换弹中受伤次数；
- 投掷物使用频率和命中目标数。

### 构筑

- 每个升级出现、选择、跳过次数；
- 第一个核心升级出现波次；
- 第 10 波标签构成；
- 死亡时主要升级组合；
- 商店锁定与刷新次数。

### 敌人与波次

- 各敌人造成伤害；
- 各波死亡率；
- 同屏峰值；
- 远程预警数量峰值；
- 精英存活时间；
- 生成预算积压。

### 素材与可读性

- 玩家是否能辨认敌人职责；
- 危险预警漏看率；
- 烟雾中目标辨认率；
- AWP 激光与敌方激光混淆率；
- UI 在 1080p、1440p、720p 的可读性。

## 8. 垂直切片通过标准

十波垂直切片只有同时满足以下条件才进入完整内容生产：

- 至少 60% 首次测试者结束后愿意立即重开；
- 测试者能说清主要死亡原因；
- 测试者在第 8～10 波能用一句话描述自己的流派；
- 尼尼负面天赋不会被描述为“系统作弊”；
- 烟雾不会被描述为“看不清所以不用”；
- 至少两把枪仅凭操作和反馈即可辨认；
- 升级没有明显超过 75% 的无条件必选；
- 普通波没有由单一敌人贡献超过 45% 的总伤害；
- 目标机器压力波保持性能预算；
- 正式素材在缩放、旋转和同屏混战中仍可读。
