# 《GOGO》设计文档包 v0.4

- **项目代号**：GOGO
- **文档版本**：v0.4
- **日期**：2026-07-31
- **定位**：俯视角、手动瞄准、流式无尽战场、20 波生存、角色怪癖驱动构筑的动作肉鸽
- **首发目标**：Windows 单机版
- **开发引擎**：Godot 4.x（当前 CI 固定使用 4.7.1 stable）
- **状态**：M0 射击底座和第一版无限荒漠灰盒原型已实现，可进入连续移动与五波闭环验证

> 本目录是项目唯一权威 GDD。仓库开发入口为根目录 `CODEX_START.md`。不要在 `docs/` 下创建另一套平行的简化设计文档。

> `arenas/` 是 `15_竞技场与刷怪空间系统.md` 的内容附录，不是第二套 GDD。`16_无尽双尘荒原与程序化模块系统.md` 是当前默认世界方向，并覆盖旧文档中“首发固定竞技场”的概述。

> 本文档包不是“所有数值已经最终平衡”的承诺。标注为“初始值”的内容用于建立可运行原型，必须通过 `10_平衡测试规范.md` 中的流程迭代。

## 2. 全局统一口径

以下约定在全部文档中具有统一约束力：

1. **肉鸽构筑是主体，战术射击是操作语言，电竞梗是角色题材。**
2. 第一版采用**单主武器制**，不做六武器同时自动攻击。
3. 玩家使用 WASD 移动、鼠标手动瞄准，按住左键按武器射速持续开火。
4. 标准模式目标仍为 20 波；普通波限时生存并清场，Boss 波以击杀目标结束。
5. 玩家携带一把主武器和两个投掷物槽位。
6. 枪械首发：USP、Deagle、AK、M4、AWP。名称与外观均视为原型标识，商业发布前单独审查。
7. 角色首发：尼尼、小洞大人、设备、上帝、大表哥。角色必须采用原创外观、经历、台词和队伍设定。
8. 第一版默认地图是**无尽双尘荒原**：单一黄沙旧城主题、固定 Seed、Chunk 流送，不显示硬边界。
9. 地图战斗结构来自人工设计模块的程序选择和旋转，不使用随机迷宫，不复刻商业地图雷达轮廓、点位和物件排列。
10. 无限地图当前基准为 `1024×1024 px` Chunk、半径 `2` 的 `5×5` 活跃集合、每帧最多构建一个 Chunk。
11. 地图、敌人和武器散布使用彼此独立的确定性随机子流。
12. 敌人只在屏幕外合法区域生成；无合法候选时延后，禁止贴脸补偿。
13. 角色负面天赋必须满足：**可预警、可规避、可构筑缓解、可后期反转**。
14. 局外成长主要解锁内容宽度，不提供大量永久伤害或生命碾压。
15. 角色、武器、投掷物、子弹、特效、UI 与场景素材必须模块化，不得画死在一起。
16. AI 生成结果必须经过清理与实机场景验收，不能直接作为最终资产。
17. 正式地图素材必须拆成地面、墙体、转角、掩体、Decal、POI 和环境动画组件，不交付一张不可拆分的大地图图。
18. 当前运行时依赖保持最小化：第一版不引入 WFC、Gaea、YATI 或第三方无限地形插件控制核心生命周期。

## 3. 文档冲突处理

当不同文档存在冲突时，按以下顺序处理：

1. `00_产品宪法.md`；
2. 后编号专项文档中的明确规则优先于前编号文档中的概述；
3. `16_无尽双尘荒原与程序化模块系统.md` 优先于旧文档中“首发固定竞技场”的描述；
4. 已通过平衡评审并记录版本号的调整优先；
5. `12_游戏性与素材Review.md` 中明确记录的本轮执行决定优先于未更新的旧建议；
6. 未经记录的临时代码行为不构成设计规则。

任何会改变产品支柱、20 波结构、单主武器制、角色负面原则或默认世界方向的改动，都需要先更新 `00_产品宪法.md`，再修改其他文档。

如果 Codex 发现规则冲突：

- 不自行选择最容易实现的版本；
- 记录冲突文件和章节；
- 优先按上面的顺序解析；
- 无法解析时停止该冲突范围，但继续完成不受影响的工作。

## 4. 给 Codex 的使用方式

不要把整个文档包一次性要求 Codex 全部实现。每次任务只选择一个可验证闭环，例如：

- 实现 `WeaponDefinition` 数据资源和 AK 的射击、后坐力、换弹；
- 验证相同世界 Seed 与 Chunk 坐标得到相同模块；
- 验证玩家跨越正负坐标时 Chunk 不重复、不出现持续内存增长；
- 实现环形刷怪候选、Terrain 过滤和无合法点延后；
- 实现 Wave 1～3 并复用无限地图的 `SpawnDirector`；
- 实现烟雾区域、远程锁定延迟和大表哥被动；
- 实现三选一候选池的标签相关性与两次未出现后的保底；
- 实现 `AssetGallery` 场景验证角色、枪械、敌人和场景模块可读性。

无限地图或刷怪任务必须阅读：

1. `00_产品宪法.md`；
2. `06_怪物与波次设计.md`；
3. `09_Godot技术架构.md`；
4. `15_竞技场与刷怪空间系统.md`；
5. `16_无尽双尘荒原与程序化模块系统.md`。

每个开发任务都必须写明：

- 允许修改的目录；
- 禁止顺手重构的范围；
- 可观察的验收步骤；
- 失败时需要保留的日志；
- 数据配置与代码逻辑的边界；
- 实际运行和测试证据。

完整执行模板见 `../../CODEX_START.md`。

## 5. 当前开发顺序

当前不进入五角色、完整 20 波或三地图的全面实现。顺序固定为：

1. **M0 射击底座**：AK 移动、瞄准、射击、后坐力、弹匣、换弹和反馈；
2. **E0 无限移动底座**：Camera2D、`5×5` Chunk 流送、每帧一个构建、超范围回收；
3. **E1 确定性战斗模块**：六种灰盒模块、旋转、Terrain 碰撞和稀疏补给站 POI；
4. **E2 动态刷怪链路**：环形候选、屏幕外和 Terrain 过滤、活动上限、对象池回收；
5. **Windows 人工门槛**：连续移动和射击十分钟，检查地图空洞、碰撞、内存、FPS 与主观手感；
6. **M1 五波闭环**：在无限荒漠底座上加入三种敌人、赏金、升级和重新开始；
7. **M2 角色战术验证**：尼尼、大表哥、烟雾和负面天赋；
8. **M3 十波垂直切片**：正式像素地图模块、第一版 HUD、小 Boss 和固定种子回归；
9. 通过门槛后，再扩展到完整五角色、五枪、47 升级和 20 波；
10. Windows 1.0 后再评估赤瓦小镇、货运枢纽、固定竞技场模式和跨平台扩展。

素材生产同步按 `assets/asset_manifest.csv` 的阶段推进，不提前批量生成未验证系统或内容储备地图的正式资产。
