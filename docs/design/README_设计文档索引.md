## 2. 全局统一口径

以下约定在全部文档中具有最高优先级：

1. **肉鸽构筑是主体，战术射击是操作语言，电竞梗是角色题材。**
2. 第一版采用**单主武器制**，不做六武器同时自动攻击。
3. 玩家使用 WASD 移动、鼠标手动瞄准，按住左键按武器射速持续开火。
4. 每局 20 波；普通波限时生存并清场，Boss 波以击杀目标结束。
5. 玩家携带一把主武器和两个投掷物槽位。
6. 枪械首发：USP、Deagle、AK、M4、AWP。名称与外观均视为原型标识，商业发布前单独审查。
7. 角色首发：尼尼、小洞大人、设备、上帝、大表哥。角色必须采用原创外观、经历、台词和队伍设定。
8. 固定大竞技场、镜头跟随玩家，不做多房间探索和随机迷宫。
9. 角色负面天赋必须满足：**可预警、可规避、可构筑缓解、可后期反转**。
10. 局外成长主要解锁内容宽度，不提供大量永久伤害或生命碾压。
11. 一切“最终数值”都要以遥测、盲测和固定种子回归结果为依据。
12. 角色、武器、投掷物、子弹、特效、UI 与场景素材必须模块化，不得画死在一起。
13. AI 生成结果必须经过清理与实机场景验收，不能直接作为最终资产。
14. 开发按 M0 射击玩具、M1 五波闭环、M2 角色战术验证、M3 十波切片、M4 内容完成、M5 发布候选推进。

## 3. 文档冲突处理

当不同文档存在冲突时，按以下顺序处理：

1. `00_产品宪法.md`；
2. 后编号文档中的专门规则优先于前编号文档中的概述；
3. 已通过平衡评审并记录版本号的调整优先；
4. `12_游戏性与素材Review.md` 中明确记录的本轮执行决定优先于未更新的旧建议；
5. 未经记录的临时代码行为不构成设计规则。

任何会改变产品支柱、20 波结构、单主武器制或角色负面天赋原则的改动，都需要先更新 `00_产品宪法.md`，再修改其他文档。

如果 Codex 发现规则冲突：

- 不自行选择最容易实现的版本；
- 记录冲突文件和章节；
- 优先按上面的顺序解析；
- 无法解析时停止该冲突范围，但继续完成不受影响的工作。

## 5. 给 Codex 的使用方式

不要把整个文档包一次性要求 Codex 全部实现。每次任务只选择一个可验证闭环，例如：

- 实现 `WeaponDef` 数据资源和 AK 的射击、后坐力、换弹；
- 实现 Wave 1～3 的 `WaveDirector` 与生成安全规则；
- 实现烟雾区域、远程锁定延迟和大表哥被动；
- 实现三选一候选池的标签相关性与两次未出现后的保底；
- 实现一组固定种子回归测试；
- 实现 `AssetGallery` 场景验证角色、枪械、敌人和特效可读性。

每个开发任务都必须引用对应文档章节，并写明：

- 允许修改的目录；
- 禁止顺手重构的范围；
- 可观察的验收步骤；
- 失败时需要保留的日志；
- 数据配置与代码逻辑的边界；
- 实际运行和测试证据。

完整执行模板见 `../../CODEX_START.md`。

## 6. 当前开发顺序

当前不进入五角色、20 波的全面实现。顺序固定为：

1. M0：AK 灰盒射击是否好玩；
2. M1：五波升级闭环是否让玩家愿意重开；
3. M2：尼尼与大表哥是否证明负面天赋和烟雾系统成立；
4. M3：十波垂直切片是否达到可对外试玩的完成度；
5. 通过门槛后，再扩展到完整五角色、五枪、47 升级和 20 波。

素材生产同步按 `assets/asset_manifest.csv` 的 A1～A5 阶段推进，不提前批量生成未验证系统的正式资产。
