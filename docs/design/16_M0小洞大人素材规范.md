- **版本**：v0.1

- **目标分支**：`docs/pixel-style-bible`
- **状态**：规范已定稿，等待成品素材阶段

- **适用范围**：M0 小洞大人八方向角色帧、独立 AK、枪口火焰、曳光、命中特效、角色侧挂点元数据与 Godot 组合方式

## 1. 目标

把当前 M0 的圆形灰盒角色替换成一套可直接接入 Godot 的最小正式素材，使玩家能够验证：

1. 小洞大人的角色识别是否成立；
2. 八方向切换是否清楚、稳定；
3. 移动循环是否可读；
4. 独立 AK 是否能稳定贴到人物手部；
5. 枪口位置、曳光、射线和命中点是否一致；
6. 这套结构是否能复用于尼尼、设备、上帝和大表哥。

M0 的成功标准不是“动画数量多”，而是：

> **人物方向正确、武器贴合稳定、射击反馈可信，连续运行时没有明显跳帧、漂移或层级错误。**

## 2. M0 核心决策

### 2.1 采用完整人物帧

小洞大人每一帧都是完整人物 PNG：

- 头、身体、双臂和双腿已经合并；
- 不再拆身体层、左手层、右手层；
- 不制作三套握持层；
- 不在角色 PNG 中画入 AK；
- 双手允许形成简化的通用持枪姿态，但手中必须为空。

这样做是为了降低 M0 的制作和运行复杂度，同时保留“人物和武器可独立更换”的能力。

### 2.2 采用八方向人物，不采用八方向武器

人物方向固定为：

```text
n, ne, e, se, s, sw, w, nw
```

人物使用八方向完整帧；AK 只生产一张枪口朝右的基础图，由 Godot 的 `WeaponPivot` 完成旋转、翻转、后坐和层级切换。

禁止为 M0 生产八张 AK 方向图。否则会重复维护枪械外观和枪口坐标，并使后续换枪成本成倍增加。

### 2.3 武器贴合使用“角色挂点 + 武器挂点”

角色侧每一帧记录 `hand_socket_stand`；武器侧继续使用已有：

- `grip_point`
- `muzzle_point`
- `shell_eject_point`
- `shoulder_point`
- `rotation_center`

Godot 将武器 `grip_point` 对齐到角色当前帧的 `hand_socket_stand`。

**`muzzle_point` 只属于武器，不为人物八方向重复登记。** 枪口火焰、曳光和子弹起点都从武器的 `muzzle_point` 派生。

### 2.4 每帧独立 PNG，不制作 Sprite Sheet

M0 最终素材一帧一个 PNG：

- 便于单帧返工；
- 便于比较八方向轮廓；
- 便于保存逐帧挂点；
- 避免 AI 生成 Sprite Sheet 时出现帧尺寸、角色比例和排列污染。

Godot 的 `SpriteFrames` 资源由导入脚本或人工配置引用这些独立 PNG。

## 3. GitHub 开源项目参考与取舍

本规范只吸收开源项目的组织和工程思想，不复制其角色、武器、特效或 UI 美术。

### 3.1 `DarkRewar/SurvivorsStarterKit`

参考：<https://github.com/DarkRewar/SurvivorsStarterKit>

吸收：

- 将对象、能力、预制场景、场景和脚本按职责分离；
- 角色、攻击方式和特效不烘焙成一个不可替换整体；
- M0 只实现最小闭环，不提前制作完整内容池。

不照搬：

- 不采用其中的具体角色、敌人、场景和法术美术；
- 不把自动索敌逻辑带入 GOGO 的鼠标手动瞄准。

### 3.2 `alextrevisan/LPCAnimatedSprite2D`

参考：<https://github.com/alextrevisan/LPCAnimatedSprite2D>

吸收：

- 动画名显式包含状态和方向，例如 `walk_south`；
- 人物动画和大型武器能够保持独立；
- 自定义动画数据应由稳定的元数据描述，而不是散落在脚本常量中。

不照搬：

- 不采用 LPC 的人物比例、Sprite Sheet 排版或素材；
- 不引入 M0 不需要的完整换装和大量动作系统。

### 3.3 `Hairic95/8-direction-sprite`

参考：<https://gist.github.com/Hairic95/7c6f9b1f454780a643e27f590cb185b9>

吸收：

- 将连续方向稳定量化为八个明确扇区；
- 八方向索引必须固定，不能由素材生产者临时决定。

不照搬：

- 参考项目用于 `Sprite3D`，GOGO 使用 `AnimatedSprite2D`；
- GOGO 不使用其 4×2 Sprite Sheet，而使用独立 PNG。

### 3.4 许可边界

本阶段不导入以上项目的代码和资产，因此不存在第三方素材再分发。未来若实际复制或修改外部代码、音效或图片，必须在 `THIRD_PARTY_NOTICES` 或对应资产目录中记录来源、作者和许可证。

## 5. 小洞大人视觉定义

### 5.1 识别锚点

M0 只保留以下三个高优先级锚点：

1. **黑色偏长发型**：两侧头发形成清楚的偏长轮廓，可覆盖耳部并向下颌附近延伸；
2. **额前不画整齐刘海**：额头应部分露出，只允许少量自然垂落发束；禁止锅盖头、厚齐刘海和夸张窗帘刘海；
3. **年轻、偏瘦、强攻击感**：脸型偏窄，身体紧凑但不能画成矮胖或肌肉壮汉。

这一定义取代 `13_素材生产管线与提示词.md` 中“小洞大人必须是清晰中分和窗帘式前发”的过度限定。可有自然发缝，但不得为了表现“中分”重新画出两片厚刘海。

### 5.2 服装

- 原创深灰或黑色训练服；
- 小面积红橙强调色，面积不超过人物主体的 10%；
- 不使用真实队服版型；
- 不使用队标、赞助商、赛事徽章、真实文字；
- 不靠复杂装备堆识别度。

### 5.3 比例与轮廓

- 最终逻辑画布：128×128；
- 角色主体高度：92～105 px；
- 头部占总高度：34%～42%；
- 外轮廓：1～2 个逻辑像素；
- 主轮廓色：`#1C1E24`；
- 左上光；
- 每帧人物局部颜色：8～14 色；
- 透明背景；
- 角色和特效之外禁止地面、投影、UI 和文字。

### 5.4 持枪姿态约束

人物帧不画枪，但双手应保持可供贴枪的紧凑姿势：

- 主手位于胸前偏外侧；
- 副手可靠近主手或护木区域；
- 双臂不能大幅摆离躯干；
- move 动画允许腿部和身体产生步态变化，但主手挂点应保持稳定；
- 不需要精确画出手指，只需保证武器覆盖后姿态可信。

## 6. 八方向与动画状态

### 6.1 坐标约定

Godot 2D 坐标：

- `+X`：向右；
- `+Y`：向下；
- 角度 `0°`：`e`；
- 角度顺时针增加。

八方向扇区固定为：

| 方向 | 角度范围 |
|---|---|
| `e` | `[-22.5°, 22.5°)` |
| `se` | `[22.5°, 67.5°)` |
| `s` | `[67.5°, 112.5°)` |
| `sw` | `[112.5°, 157.5°)` |
| `w` | `[157.5°, 180°]` 或 `[-180°, -157.5°)` |
| `nw` | `[-157.5°, -112.5°)` |
| `n` | `[-112.5°, -67.5°)` |
| `ne` | `[-67.5°, -22.5°)` |

扇区边界必须只在代码中定义一次，测试和运行共用同一函数。

### 6.2 人物朝向来源

M0 的人物朝向由 **鼠标瞄准方向 `aim_dir`** 决定，不由移动方向决定。

状态由移动速度决定：

- `velocity.length() <= idle_threshold`：播放 `idle_<direction>`；
- `velocity.length() > idle_threshold`：播放 `move_<direction>`。

因此角色可以面向鼠标移动、侧移或后退。M0 接受这种简化，不额外制作前进、侧移、后退三套步态。

### 6.3 播放规则

| 动画 | 帧数 | 循环 | 建议速度 |
|---|---:|---|---:|
| `idle_<dir>` | 1 | 静止 | 0 fps |
| `move_<dir>` | 4 | 是 | 8 fps |
| `fx_muzzle_ak` | 3 | 否 | 24 fps |
| `fx_hit_spark_small` | 3 | 否 | 20 fps |

`move` 四帧建议节奏：

1. 左脚推进；
2. 身体回中；
3. 右脚推进；
4. 身体回中。

禁止使用明显上下弹跳掩盖脚步。头顶和脚底总体基线必须稳定。

## 7. 画布与固定锚点

### 7.1 人物画布

- 逻辑画布：128×128；
- 坐标原点：左上角；
- 固定根锚点：`feet_center = [64, 112]`；
- 建议身体参考中心：`body_center = [64, 72]`；
- 人物像素不得越过画布；
- 每帧根锚点不随身体起伏移动。

人物可以在根锚点上方产生轻微步态变化，但双脚中点相对根锚点的漂移不得超过 2 px。

### 7.2 每帧角色挂点

每一帧必须登记：

- `feet_center`
- `body_center`
- `hand_socket_stand`

可选登记：

- `offhand_hint`
- `head_center`

其中：

- `hand_socket_stand` 是 AK 的唯一角色侧连接点；
- `offhand_hint` 只用于人工检查护木位置，不作为 Godot 必需挂点；
- 同一方向的四个 move 帧中，`hand_socket_stand` 相邻帧跳动不得超过 2 px；
- 不允许通过在角色 PNG 中画一小截枪托来隐藏挂点错误。

### 7.3 AK 画布与挂点

AK 继续使用全局武器规范：

- 逻辑画布：160×96；
- 基础方向：向右；
- `grip_point = [68, 58]`；
- `muzzle_point = [151, 40]`；
- `shell_eject_point = [91, 34]`；
- `shoulder_point = [26, 56]`；
- `rotation_center = [68, 58]`；
- `logical_length = 132`。

这些值来自 `assets/weapons/weapon_attachment_spec.json`。M0 不得另建一套冲突坐标。

### 7.4 特效画布

| 特效 | 逻辑画布 | 默认锚点 |
|---|---:|---|
| 枪口火焰 | 64×64 | 左侧根部中心，贴 `muzzle_point` |
| 曳光 | 64×64 | 中心，默认水平向右 |
| 命中火花 | 64×64 | 中心，贴实际命中点 |

特效可以使用透明度渐隐；人物和武器边缘必须保持硬像素，不得保留半透明脏边。

## 9. 文件命名

### 9.1 人物

统一格式：

```text
character_xiaodong_<state>_<direction>_f<frame>_v<version>.png
```

示例：

```text
character_xiaodong_idle_se_f00_v01.png
character_xiaodong_move_n_f00_v01.png
character_xiaodong_move_n_f01_v01.png
character_xiaodong_move_n_f02_v01.png
character_xiaodong_move_n_f03_v01.png
```

硬规则：

- 帧编号固定两位，从 `f00` 开始；
- 版本固定两位，从 `v01` 开始；
- 禁止 `final`、`final2`、`new`、`ok` 等不可追踪后缀；
- idle 虽只有一帧，仍保留 `f00`。

### 9.2 武器和特效

```text
weapon_ak_base_v01.png
fx_muzzle_ak_f00_v01.png
fx_muzzle_ak_f01_v01.png
fx_muzzle_ak_f02_v01.png
fx_tracer_ak_v01.png
fx_hit_spark_small_f00_v01.png
fx_hit_spark_small_f01_v01.png
fx_hit_spark_small_f02_v01.png
```

```json
{
  "version": "1.0",
  "character_id": "xiaodong",
  "milestone": "m0",
  "canvas": [128, 128],
  "direction_source": "aim_dir",
  "directions": ["n", "ne", "e", "se", "s", "sw", "w", "nw"],
  "animations": {
    "idle": {
      "frames_per_direction": 1,
      "fps": 0,
      "loop": false,
      "path_pattern": "../idle/character_xiaodong_idle_{dir}_f00_v01.png"
    },
    "move": {
      "frames_per_direction": 4,
      "fps": 8,
      "loop": true,
      "path_pattern": "../move/character_xiaodong_move_{dir}_f{frame}_v01.png"
    }
  },
  "anchor_map": "xiaodong_m0_anchor_map.json"
}
```

### 10.2 `xiaodong_m0_anchor_map.json`

最低字段：

```json
{
  "version": "1.0",
  "canvas": [128, 128],
  "origin": "top_left",
  "required_points": ["feet_center", "body_center", "hand_socket_stand"],
  "frames": {
    "idle_se_f00": {
      "feet_center": [64, 112],
      "body_center": [64, 72],
      "hand_socket_stand": [72, 70],
      "offhand_hint": [80, 67]
    }
  }
}
```

示例坐标只说明格式，不代表最终美术坐标。最终值必须在图片清理完成后逐帧测量。

### 10.3 `ak_m0_meta.json`

```json
{

  "milestone": "m0",
  "texture": "weapon_ak_base_v01.png",
  "attachment_spec": "../../weapon_attachment_spec.json#/weapons/ak"
}
```

## 11. Godot 组合方式

### 11.1 节点结构

```text
Player
├── BodySprite              # AnimatedSprite2D
├── WeaponPivot             # Node2D，位置来自当前帧 hand_socket_stand
│   ├── WeaponSprite        # Sprite2D
│   ├── MuzzleSocket        # Marker2D
│   └── ShellEjectSocket    # Marker2D，M0 可不播放弹壳
├── CharacterFx             # Node2D
└── UiAnchor                # Marker2D
```

### 11.2 每帧更新顺序

1. 从鼠标方向计算连续 `aim_dir`；
2. 将 `aim_dir` 量化为八方向人物索引；
3. 根据速度选择 `idle` 或 `move`；
4. 播放对应人物帧；
5. 从 anchor map 读取当前帧的 `hand_socket_stand`；
6. 将 `WeaponPivot.position` 放到该挂点；
7. 将 AK 的 `grip_point` 对齐 `WeaponPivot`；
8. 武器继续朝连续 `aim_dir` 旋转，而不是只旋转八个角度；
9. 根据 `aim_dir.y` 应用现有前后层级规则；
10. 射击时从 AK `muzzle_point` 的全局位置生成枪口火焰、曳光和射线。

### 11.3 前后层级

继续使用 `15_武器道具与升级图标资产设计.md` 的规则：

- `aim_dir.y >= -0.20`：武器在人物前方；
- `aim_dir.y < -0.20`：武器在人物后方。

人物朝北、东北、西北时，应重点检查枪身是否错误覆盖脸部和头发。

### 11.4 射线一致性

射击方向必须从枪口位置指向鼠标目标：

```text
shot_direction = (target_position - muzzle_global_position).normalized()
```

禁止继续从人物中心生成视觉曳光、却从枪口显示火焰。射线、曳光、命中位置必须共用同一次射击结果。

## 12. 成品生产顺序

第二阶段必须按以下顺序执行：

1. 选定并清理 `idle_se_f00` 作为角色母版；
2. 单独验收发型、脸型、比例、服装和 128×128 实际尺寸；
3. 基于母版制作其余七个 idle 方向；
4. 八方向 idle 全部通过后，再制作 move 四帧循环；
5. 清理独立 AK 并验证 `grip_point`、`muzzle_point`；
6. 在 Godot 中完成八方向挂点预览；
7. 最后制作枪口火焰、曳光和命中火花；
8. 完成 manifest、anchor map 和 M0 集成验收。

当前分支已有方向草稿只能作为参考，不自动视为正式成品。任何草稿进入正式目录前都必须满足本文件的尺寸、命名、透明边缘、挂点和实际游戏预览要求。

## 13. 验收标准

### 13.1 文件完整性

- [ ] 40 张人物帧全部存在；
- [ ] 1 张 AK 存在；
- [ ] 7 张特效帧存在；
- [ ] 三个 JSON 元数据文件存在；
- [ ] manifest 中所有路径均能解析；
- [ ] 不存在 Sprite Sheet；
- [ ] 不存在 `final2`、`new` 等临时命名。

### 13.2 视觉验收

- [ ] 八方向在实际游戏尺寸下 0.5 秒内可辨认；
- [ ] 小洞大人的偏长黑发、露额头和窄脸成立；
- [ ] 没有厚刘海、锅盖头或两片窗帘刘海；
- [ ] 八方向头身比例一致；
- [ ] 角色没有真实队服、Logo、赞助商或可读文字；
- [ ] 左上光、轮廓和色板与 Style Bible 一致；
- [ ] 人物和武器没有半透明脏边；
- [ ] 缩小到 128×128 后脸、头发和朝向仍清楚。

### 13.3 动画验收

- [ ] 每方向 move 四帧可无缝循环；
- [ ] 方向切换时人物脚底不跳动；
- [ ] 相邻 move 帧根锚点漂移不超过 2 px；
- [ ] 主手挂点相邻帧跳动不超过 2 px；
- [ ] 身体起伏不会导致武器明显悬空或穿胸；
- [ ] 连续移动时没有角色尺寸忽大忽小。

### 13.4 武器与射击验收

- [ ] AK 可由一张基础图覆盖全角度瞄准；
- [ ] 八方向人物切换时 AK 不会突然跳到另一侧；
- [ ] 枪托不会大面积穿入胸口或头部；
- [ ] 枪口火焰始终位于 `muzzle_point`；
- [ ] 曳光起点与射线起点一致；
- [ ] 命中火花出现在真实碰撞点；
- [ ] 朝北方向武器层级正确；
- [ ] 向左瞄准时翻转后挂点和枪口位置正确。

### 13.5 M0 运行验收

- [ ] Windows 真机连续运行 10 分钟无脚本错误；
- [ ] WASD 移动、鼠标瞄准和持续射击正常；
- [ ] 八方向临界角附近无高频抖动；
- [ ] 角色状态只在 idle/move 间切换，不误触发不存在动作；
- [ ] 不修改 `.DS_Store`；
- [ ] 不因素材替换破坏 `project.godot` 中无关配置；
- [ ] 现有 M0 弹匣、后坐、换弹和命中测试继续通过。

## 14. 返工与拒收规则

出现以下任一情况，单帧或整组素材必须退回：

1. 发型与母版不一致，尤其重新出现厚刘海或锅盖头；
2. 人物方向只是机械镜像，导致发型、光源和手部逻辑错误；
3. 手部挂点漂移超过 2 px；
4. 武器被画进人物 PNG；
5. 用八方向 AK 绕过挂点问题；
6. AI 原图未经硬边清理直接进入正式目录；
7. 角色脚底、尺寸或身体中心在动画中明显漂移；
8. 枪口火焰、曳光和实际射线不同源；
9. 使用真实队服、Logo、赞助商、赛事标识；
10. 只在放大预览中好看，实际尺寸无法辨认。
