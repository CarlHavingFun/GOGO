# 13｜素材生产管线与提示词

## 1. 目的和唯一生产入口

GOGO 的正式角色、武器、特效、地图和动画素材统一采用固定版本的 Agent Sprite Forge 思路：Agent 负责规划，内置 `image_gen` 负责 raw 视觉，仓库脚本负责确定性清理、切帧、对齐、组装、验证和 Godot 交付。

固定上游版本：

```text
repository: https://github.com/0x0funky/agent-sprite-forge
commit: 64fd0b57d3f2ae117ef0a95e4c2decc25b4c9dd2
license: MIT
```

Codex 默认只接入 `generate2dsprite` 和 `generate2dmap`。`video2dsprite` 依赖 Grok 专属视频生成能力，不作为 GOGO 默认流程。

正式资产不得把 raw 生图文件直接当作运行时 Sprite。所有交付必须有 manifest 登记、Prompt、pipeline metadata、清理结果、QA 记录和 Godot 导入证据。

## 2. 状态和门禁

每个资产先登记 `planned`，再按以下顺序推进：

```text
planned → generated → cleaned → approved → in_game
                         ↘ rejected
```

- `planned`：允许证据字段为空，但运行时路径可以是规划路径。
- `generated`：必须有 `forge_mode`、`raw_layout`、`prompt_path` 和 `source_output`。
- `cleaned`：必须有 `pipeline_meta` 和 `cleaned_output`，且保留切帧/对齐信息。
- `approved` / `in_game`：必须有 QA、reviewer 和 Godot evidence。
- `rejected`：不得保留稳定运行时路径，重新生成必须新建版本或记录替代关系。

## 3. 开始前检查

1. 读取本文件、`assets/README.md` 和当前 `assets/asset_manifest.csv`。
2. 确认设计阶段 `A0–A5`、内容阶段 `C0`、原创/IP policy 和 Godot 运行时契约。
3. 先登记 `planned`，明确 `asset_id`、类别、动作、视角、逻辑画布、锚点、帧数、FPS、方向、引用和碰撞语义。
4. 本地参考图必须先通过图片查看工具可见化，再作为 image generation reference；不能只把未知路径写入 Prompt。
5. 高价值连续动作共享 `scale_profile`，禁止每个动作各自猜角色比例。

## 4. Raw 生成规则

手写 Prompt 必须明确：

- 俯视角/侧向信息、角色朝向、动作、动作语义和帧序；
- 纯 `#FF00FF` 原始背景、透明化目标和安全区域；
- 逻辑画布、生成画布、脚底/枪械/枪口锚点；
- GOGO Style Bible 的像素边缘、限制色板、无文字、无 Logo、无水印、无环境和无额外肢体约束；
- 参考图的用途和不复制具体作品资产的原创/IP 约束。

角色主体默认采用多行 raw 网格，不直接要求最终 Godot 横条：

| 需求 | Raw 网格 |
|---|---|
| 4 帧 | `2x2` |
| 6 帧 | `2x3` |
| 8 帧 | `2x4` |
| 四方向走路 | `4x4` |

不要生成把 idle、walk、hit、death、技能混在一起的 raw atlas。角色主体、武器、枪口火焰、投射物和命中特效必须分层生成。

推荐 Prompt 骨架：

```text
GOGO 2D top-down pixel sprite, [subject], [action], [view/direction],
[frame count and grid], consistent feet/hand/muzzle anchors,
logical canvas [W]x[H], safe margin [N] px, centered subject,
flat pure #FF00FF background, crisp stepped pixel edges,
limited palette from the GOGO Style Bible, no text, no logo, no watermark.
Separate [body/weapon/fx] layer; preserve scale profile [name].
Negative: photorealism, 3D render, vector art, blur, cast shadow,
environment, extra limbs, cropped feet, broken silhouette, mixed actions.
```

## 5. 清理、切帧和 QC

对每个动作独立执行：

1. 检查 raw 是否是预期网格，背景是否纯 `#FF00FF`，主体是否触碰安全边界。
2. 确定性去背景、裁切、保持逻辑画布、恢复统一锚点。
3. 按 raw 网格切帧，并输出独立 PNG、预览图和可选 GIF；不靠手工拖动决定帧顺序。
4. 对齐脚底、握点、枪口、投射点和命中中心；记录偏移而不是偷偷修图。
5. 严格 QC：帧数、尺寸、透明边缘、色板、轮廓、比例、动作连续性、重复帧、越界、背景残留、意外文字和 IP 风险。
6. QC 通过后，才将 raw 多行网格确定性组装成 Godot 所需的横向条带或最终图集，并填写 `sprite_layout`。

`raw_layout` 描述生成输入布局；`sprite_layout` 只描述最终运行时交付布局。二者不能混写。任何连续动作出现两轮同类错误时，必须修改 Prompt、参考图、scale profile 或拆分资产，禁止盲目重生成。

## 6. 地图管线

地图使用 `generate2dmap` 规划，但可玩地图不能是一张烘焙大图。至少拆分：

- 基础地面/重复纹理；
- 独立 props 和可替换模块；
- 碰撞数据；
- 区域、出生安全区和 POI；
- Godot 场景元数据和模块 Seed。

无尽荒漠的地面与模块优先由 `src/arena/` 的程序化组件生成；AI 图只用于经过登记和 QC 的视觉层，不取代 Chunk 碰撞和流送契约。

## 7. 证据结构

每次生成至少关联：

```text
assets/source/generated/.../prompt-used.txt
assets/source/generated/.../pipeline-meta.json
assets/source/cleaned/.../frames/*.png
assets/source/cleaned/.../qa.json
assets/.../delivery.png
assets/.../godot-evidence.png 或 docs/progress/... 记录
```

Manifest 字段含义：

| 字段 | 含义 |
|---|---|
| `forge_mode` | `generate2dsprite`、`generate2dmap`、`runtime_native` 或 `procedural_placeholder` |
| `raw_layout` | raw 网格，如 `2x2`、`4x4`、`scene_layers` |
| `sprite_layout` | 最终运行时交付布局，如 `horizontal_4x1`、`single` 或 `scene_metadata` |
| `prompt_path` | 实际使用的 Prompt 文件 |
| `pipeline_meta` | 原图、脚本版本、切帧、对齐和输出元数据 |
| `scale_profile` | 共享角色比例/锚点配置 |

## 8. GOGO 阶段映射

- `A0`：参考、原创边界和资产卡；
- `A1–A4`：按当前里程碑生产武器、敌人、特效和场景层；
- `A5`：角色交付和运行时证据；
- `C0`：角色设计治理，只允许改变设计卡和候选状态，不自动越过 A5；
- `G0`：manifest、引用、Prompt 约束和状态门禁通过；
- `M0`：只接入回归所需的最小素材，继续允许灰盒占位；
- `M5`：经过人工体验、版权/IP 和 Godot 运行时验收后才作为正式发布资产。

## 9. 失败处理

以下任一项失败都停在当前状态：背景不纯、主体被裁、锚点漂移、帧间比例变化、混入另一动作、透明边残留、文字/Logo、水印、运行时路径未注册、Godot 导入不一致或参考权利不明确。重新生成前先更新 Prompt、参考图、scale profile 或资产拆分，并保留失败证据。
